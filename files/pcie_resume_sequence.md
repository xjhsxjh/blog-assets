# PCIe 拓扑结构标准唤醒流程 (ARM64 Linux)

本流程描述系统从休眠状态被唤醒时（可由外部电源键或 PCIe 外设 WAKE# 信号触发），整个 PCIe 拓扑结构如何经历“上电 -> 硬件复位 -> 链路训练 -> 配置恢复”并最终回到 D0 满电工作状态的过程。

---

## 阶段一：触发源响应与平台供电恢复 (D3cold -> L2/L3)
1. **触发唤醒信号**：
   * **带外唤醒 (常用)**：处于 Vaux 供电下的设备（如网卡）收到唤醒事件，拉低 **WAKE#** 引脚。该引脚连接至 SoC 具备唤醒功能的 GPIO，触发中断。
   * **平台唤醒**：用户按下电源键，SoC 电源管理单元（PMU）或 ATF（Arm Trusted Firmware）被唤醒。
2. **恢复主电源 Vcc**：
   * Linux PMU 电源域驱动或板级 Regulator 驱动响应，重新控制 PMIC 打开对应 PCIe 插槽或外设的 **Vcc 主供电**。
   * 设备从 D3cold 退出。此时由于经历过彻底断电，外设内部的所有寄存器内容已全部丢失。

## 阶段二：硬件复位与链路训练 (LTSSM 转换 -> L0)
3. **强制硬件复位 (PERST#)**：
   * 为确保断电后重新上电的稳定性，RC 硬件或 GPIO 驱动会拉低并维持一段时间的 **PERST#** 复位信号，然后再拉高释放。
   * 这一时序必须严格满足 PCIe 规范（通常需等待电源稳定后释放复位），以防止下行 Switch 或叶子设备由于复位未就绪而“失联”。
4. **链路训练 (Link Training)**：
   * 复位释放后，PCIe 控制器物理层自动启动 LTSSM 状态机转换。
   * 链路开始逐层训练：RC <-> Switch 链路首先建立，随后 Switch <-> 各叶子设备（NVMe、网卡等）的链路建立，全拓扑链路恢复至 **L0**（正常传输状态）。

## 阶段三：配置空间恢复与驱动业务重开 (由上至下)
5. **RC 驱动恢复**：ARM64 RC 驱动首先执行 `resume()`，初始化并恢复 PCIe 控制器自身的基础基地址及控制寄存器。
6. **由上至下恢复配置空间 (D3hot -> D0)**：
   * Linux PCI 核心层利用休眠前备份在内存中的数据，**从上至下**（RC -> Switch -> 终端设备）重新写入各自的 Configuration Space。
   * 重新配置基地址寄存器（BAR）、中断向量表（MSI/MSI-X）、Command 寄存器等。
   * 写入设备的 `PMCSR` 寄存器，将其状态从 D3hot 显式迁移回 **D0**。
7. **调用叶子设备驱动的 Resume**：
   * **NVMe 驱动**：重新初始化 NVMe 控制器底层，重新创建 Admin/IO 队列，恢复块设备层映射。
   * **网卡/Wi-Fi 驱动**：恢复 MAC 寄存器，重新使能 DMA 与网卡接收/发送队列，使能网络数据传输。
   * **USB Hub 驱动**：重新使能下行端口，重新枚举或恢复连接的 USB 子设备。
8. **解冻进程**：Linux PM Core 完成所有总线及设备的 `resume` 后，解冻用户空间进程，系统完全恢复正常运行。
